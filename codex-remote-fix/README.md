# Codex Remote Fix

用于 macOS 的 Codex 技能与排查指南。先诊断，再根据证据修复 Remote Control 无法启用的问题。

适用症状：点击“控制这台 Mac → 允许”后提示“无法启用远程控制”，或“请确保仅有一个 ChatGPT 实例在运行”。相同提示可能有不同原因，本方案按证据逐步处理。

## 本次案例的真实结果

- ChatGPT Desktop：26.930.31428；内置 Codex CLI：0.160.0。
- Mac 系统使用本机代理，代理环境变量未设置；respect_system_proxy 原来关闭。
- 启用该功能后，doctor 的 WebSocket 检查从超时变为成功（HTTP 101）。
- 独立 Remote Control 服务成功启动并生成配对码，但桌面设置仍报错。因此不能宣称整个问题已经解决。
- 应用完全重启后提示变成“仅有一个 ChatGPT 实例”。检查发现只有一个应用主进程，同时诊断启动的独立 daemon 仍在运行。
- 已停止独立 daemon，保留代理功能设置。桌面重试和手机完整连接结果尚未确认；daemon 冲突是待验证解释，而非已证实根因。

## 处理步骤

1. **先查版本和原始错误。** 使用内置 CLI 检查 `codex --version`、`codex doctor --no-color`、`codex remote-control --help` 和 `codex features list`。不同版本命令可能不同，不要直接套用不存在的子命令。
2. **检查代理。** 检查 macOS 系统代理、VPN，以及 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、WSS_PROXY 和小写形式。环境变量为空不代表系统代理关闭。沙箱内网络失败须与真实系统网络区分。
3. **满足条件才启用系统代理功能。** 若系统代理正在使用、本机支持该功能且功能关闭，执行 `codex features enable respect_system_proxy`。完全退出桌面应用再打开，并重新检查网络和启用界面。
4. **按需测试独立服务。** `codex remote-control start` 和 `codex remote-control pair` 可帮助判断服务是否能够注册、配对。生成配对码只能证明这个服务成功，不能证明桌面界面修复。
5. **处理单实例提示。** 检查应用主进程与独立 daemon。多个 Helper/Renderer 是正常现象。若诊断新启动了独立服务，执行 `codex remote-control stop`，再回到桌面重试；必要时完全退出桌面并重开。不要随意杀全部 Codex 进程或删除锁文件。
6. **最后验证手机。** 手机登录同一账号和工作区，在 Codex/Remote 中添加设备，按实际界面扫码或输入短时配对码。电脑在线且能打开电脑端聊天并发送消息，才算完整通过。

若没有系统代理，或网络已通过但界面仍失败，不要继续重复启用代理。依据最新日志检查版本、服务占用和账号状态；在证据支持时更新应用或联系官方支持。

## 改动边界

不删除数据、不修改 Git 仓库、不重置系统网络。清除代理环境变量、改 VPN/代理软件配置、重新登录、撤销设备授权或重装应用前，应取得用户确认。分享诊断材料前隐藏账号标识、令牌、代理凭据和配对码。

## 安装与使用

分享 `codex-remote-fix` 文件夹或压缩包。将文件夹放入自己的 Codex 技能目录（通常为 `~/.codex/skills/`），按本机方式重新加载技能后，发送：

> 请使用 $codex-remote-fix 排查这台 Mac 的远程控制失败。先做非破坏性检查，根据证据修复，并分别验证桌面启用、配对和手机连接；影响账号或代理配置的操作先确认。

技能不包含本案例的配对码或用户机器标识，也不预设其他人的代理端口。

官方 Remote 使用背景：[从手机控制 Codex 工作](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)。本文的命令与排查分支来自本机实际检查，不是官方对所有同类错误的修复保证。

### 手动安装

先阅读技能内容，再将 `codex-remote-fix` 文件夹复制到 `~/.codex/skills/`（若设置了 CODEX_HOME，使用对应的 skills 目录）。已有同名技能时先备份，避免覆盖本地修改。重新加载或重启 Codex 后使用上述提示词。

### 移除与恢复

移除安装的技能文件夹只会取消技能，不会回滚排查时做出的配置修改。是否停用系统代理功能或停止远程服务，应根据排查前状态和当前使用情况决定。

欢迎提交新的版本兼容性信息与已验证修复。请区分事实、推测和验收结果；不要把单个案例扩展为所有用户的默认操作。
